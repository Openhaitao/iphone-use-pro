# 0.3.0 检查与优化

检查范围：主程序全部 Swift 文件、原生桥接、构建/启动脚本及附带第三方目录。未对 UxPlay 上游协议实现进行逐行审计。

## 修复

- 独立 HTTPRequestParser：拒绝负数/溢出/重复 Content-Length、超大请求、无效 JSON 和不支持的分块编码；请求连接设超时，避免无限等待残缺请求。修复负长度切片导致崩溃的可能性。
- 接口参数验证：限制截图尺寸、动作持续时间和相对移动，拒绝布尔值、非有限数和越界坐标，避免无效转换或长时间动作占用。
- 蓝牙状态在自身队列同步读取；蓝牙状态重置时清理旧订阅、外发报告及主机缓存，避免使用过期 GATT 对象。
- 视频接收按解码队列施加背压，避免无界排队增加内存及画面延迟。未测量性能改善幅度。
- 去掉没有调用者的视频尺寸通知，修正显式 VideoToolbox 解码实现的过时注释。
- 启动脚本增加 HTTP 就绪检查，修复实际运行发现的中文标点紧接 shell 变量名造成的输出失败。
- 保留 Eject 屏幕键盘切换，更新 MCP 工具说明与无画面错误提示。

## 清理与合并

移除第三方原应用 Swift 源码、独立 Package、网页 UI、打包和实验脚本、包含 WDA 下载的 bootstrap。保留本项目需要的 native、UxPlay 源码和许可文件，桥接头只同步到根目录 Sources。删除旧 USB 预编译副本、演示 GIF 和未使用的录屏辅助脚本；USB 捕获源代码与 MCP 接口保留。

升级前已保留本地源码备份。

## 验证

- 五项 XCTest 测试通过：HTTP 分片 JSON、异常 HTTP 长度/编码、动作数值限制、未知按键、混合 Annex-B 起始码。
- 原生库与 Release App 构建通过；签名与 shell 语法检查通过。
- 桌面升级版已启动，BLE 自动重连。负数/超大长度及分块请求实测返回 400，服务继续运行。
- 用户重新连接后，桌面 0.3.0 实际通过 Spotlight 搜索并打开计算器，逐步点击 7×8=56，已从新 AirPlay 截图核对结果。升级版继续运行。

## 保留限制

Apple Silicon/macOS 27+ 开发预览；未完成第二台 Mac、长时间运行、锁屏和重连验收。快速点击可靠性尚未证明改善。AirPlay/蓝牙依然依赖 iOS 授权与前台可操作状态。此轮没有实现纯蓝牙图像传输、Tailscale 或 Windows。

## 自适应等待与连续输入后续验证

8项回归测试通过。实际MCP三轮计算器7×8=56均核对通过；12次点击含等待和回图约389～607ms，原固定等待路径理论下限约800ms（没有在本次运行中进行同场A/B）。无变化的cmd+A正确返回1.2s超时信息，App启动动画较长时等待约875ms，避免过早回图。另三轮直接HTTP连续点击由120ms动作空隙节流，均得到56，每四次点击接口总耗时约1.17秒。小样本不代表所有App稳定，不承诺彻底消除漏输入。
